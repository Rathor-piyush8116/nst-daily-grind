## Problem Statement

The canteen app is kept in a Git repository named shop. Last night some files were damaged by mistake, and one good change was made. Git still has the newest committed version of every file, so you can repair the damage without typing the files again.

Starting folders

shop/ a Git repository with two commits
├── app.py damaged: its text was replaced by mistake
├── data.csv missing: it was deleted by mistake
├── README.md has a new "Usage" section: this change is good
└── style.css changed by mistake, and this change is already staged

Your commands start in the folder that contains shop, so first move into shop.

A staged change has already been added for the next commit, but it is not committed yet.

Tasks

Do the tasks in this order.

 * Repair app.py and data.csv. Bring both files back exactly as they are in the newest commit.

 * Unstage style.css, but keep its change. Take style.css out of the next commit. Do not throw away its new text: the designer wants to look at it later.

 * Commit only the good change. Add only README.md, and commit it with the message Update usage section.

Hint: Ask Git for the status of the folder at the start and after each task. It names each changed file and says how to undo each kind of change.
